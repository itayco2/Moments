# PREFLIGHT

Every defect found while building Moments, with the number that exposed it and the number after the fix.
A row is closed only when its number after is measured.

| # | what was wrong | the number that showed it | fix | the number after |
|---|---|---|---|---|
| PF01 | the model's processor imports a Gemma 4 image module that needs torchvision, which sentence-transformers does not install | `ModuleNotFoundError: torchvision` on load, 0 embeddings | `torchvision` from the same cu130 index as torch, so the two always match | `torchvision 0.29.1+cu130`; the gate loads the model in 12.8 s, 1.40 GiB on the GPU |
| PF02 | video files are decoded with torchcodec by default, and the torchvision fallback was removed in 0.26; torchcodec on Windows needs shared FFmpeg DLLs | `ImportError: torchcodec is not installed` on the first video | decode with PyAV (ships its own FFmpeg) at 1 fps, 360p short side, and pass frames to the model | gate: 2 clips in 1.94 s, peak 1.82 GiB; "a red screen" picks the red clip and "a blue screen" the blue one, smallest margin +0.092 |
| PF03 | the fast test tier imported torch through the indexing module | 6 tests in 41.7 s | torch and sentence-transformers imported only where a model is used | 6 tests in 1.12 s |
| PF04 | a batch of 16 windows needs more memory than an 8 GB card has free, and Windows spills it into shared system memory instead of failing | 0.8 windows/s at batch 16 (peak 5.81 GiB) against 2.12/s at batch 8 (3.61 GiB) | batch 8 is the default; `scripts/bench_index.py` measures sustained throughput per setting | full 3 h index at batch 8: 1.75 windows/s, peak 3.61 GiB, no spill |
| PF05 | two of the demo's example queries asked for things the footage does not contain | the Earth video's 263 contact-sheet frames hold 0 night frames, so no city lights or auroras exist to find | examples replaced with phrasings tested against the index; four such queries kept in the eval as negatives | negatives' best wrong match scores 0.62 to 0.72, below the median correct first hit (0.78) |
| PF06 | adjacent windows of one shot filled the result list with the same scene | "a hurricane seen from space" returned 32:16, 32:24 and 32:32 as its top three | windows within 4 s of a kept result are absorbed into it, and the kept span grows so the whole shot merges | six distinct moments for the same query; `test_search_merges_adjacent_windows_of_one_shot` locks it |
| PF07 | the first search after start pays CUDA's one-time setup | 1,306 ms for the first query against 188 ms for the next | one warm-up search before the server accepts requests | first query after a restart: 151 ms; the next three 113 to 170 ms |
| PF09 | the search server and the indexer each hold a copy of the model; together they overflow the 8 GB card and Windows spills silently | 547 single frames in about 10 min (0.9/s) with the server up, GPU at 100% and 5.6 GiB used | stop the server while indexing; the indexer prints free GPU memory after loading and warns under 4 GiB | 248 frames/min (4.1/s) within a minute of stopping the server, GPU at 9% (now decode-bound) |
| PF08 | the vision budget of 140 tokens per frame was the model default, not a measured choice | 140 tokens: 25.0 min for 3 h of video, 3.61 GiB, 37/53 first-place hits | measured 70 tokens on the same 53 queries | 70 tokens: 16.5 min, 2.48 GiB, 39/53 first-place hits (within noise of 140); 70 is now the default |
